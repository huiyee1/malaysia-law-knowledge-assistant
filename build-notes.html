The basis

Why retrieval, and not just a good prompt.

Ask any general model about Malaysian law and it will produce confident, well-formed, wrong answers — invented section numbers, plausible-sounding case citations, provisions that don't exist. The failure mode isn't ignorance, it's fluency without a source.

So the model is never asked to recall Malaysian law. It's given the relevant statute text at question time and told to answer only from that, citing the section. This is retrieval-augmented generation, and for legal work its real value isn't accuracy alone — it's that every claim traces to a section you can go read yourself.

That reframes the project. The model is a commodity; the corpus is the work. Roughly 80% of the effort here went into turning 6,532 government PDFs into clean, section-addressable text.

How it works

Three stages. The first runs on your laptop, the second uploads once, the third runs per question.

01Buildlocal
  • 6,532 AGC PDFs (12.4 GB)
  • Drop repealed, scanned, superseded
  • Extract text with PyMuPDF
  • Strip TOC, footnotes, running heads
  • Split into individual sections
  • → sections.jsonl
02Indexonce
  • Regroup sections by Act
  • Stamp each with its citation header
  • Attach act number as metadata
  • Upload to Gemini File Search
  • Google chunks and embeds it
  • → File Search store
03Askper question
  • Question enters the Streamlit UI
  • File Search returns matching sections
  • Gemini reads them under strict rules
  • Answer cites Act and section
  • Refuses when nothing matches
  • → cited answer
04Checkafter any change
  • 22 questions, answers known in advance
  • Right Act, right section, right figure
  • Refusals for law outside the corpus
  • Cross-act traps on shared vocabulary
  • Diff against the previous run
  • → pass / fail per case

Everything runs on your machine except the retrieval store and the model itself. There is no server to deploy and nothing to host.

Four decisions that shaped it

Each of these could have gone the other way. Here's why they didn't.

Split by section, not by page
Default chunking slices text every ~200 tokens on whitespace, cutting subsections in half. Splitting on the Act's own structure means each chunk is a legally coherent unit that carries its own citation.
Citations became possible
Index 700 MB, not 12.4 GB
Of eight downloaded categories, only updated (current consolidated Acts) is used. revised and translated are ~82% scanned images duplicating content already present. repealed is excluded outright — a system that returns repealed law as current is worse than no system.
11.7 GB deliberately unused
Rent the vector database
Gemini File Search handles storage, chunking, embedding and retrieval. That removes roughly 200 lines of database plumbing and the operational burden that comes with it. The trade is less control over chunking — worked around by pre-splitting sections before upload.
Storage free, index once
Put the safety in the prompt, not the code
The system prompt is the actual product surface. It forbids answering from memory, mandates a section citation per claim, bans advice phrasing, and requires the assistant to declare when a question needs case law or state enactments it doesn't hold.
Tune this, not the model

Step by step

From an empty folder to a running chatbot. Commands assume the Anaconda interpreter, since python isn't on PATH on this machine.

  1. Get the source documents

    download_lom.py pulls every federal Act from the Attorney General's Chambers portal at 1 request/second, resumable, writing a manifest as it goes. This produced 6,532 PDFs across eight categories.

    python download_lom.py --all

  2. Install dependencies

    pip install -r requirements.txt

    PyMuPDF for PDF text, google-genai for the API, Streamlit for the interface.

  3. Build the corpus

    Extract, clean and section-split. Start with --test to check 20 Acts before committing to the full run.

    python build_corpus.py --test
python build_corpus.py

    Produces corpus/sections.jsonl (one record per section), skipped.csv (files needing OCR) and report.txt.

  4. Set the API key

    Create a key at aistudio.google.com. Use the paid tier before any real user touches this — on the free tier, prompts may be used to improve Google's products, and this app receives people's actual legal problems.

    setx GEMINI_API_KEY "your-key-here"

    setx only affects processes started afterwards. Open a new terminal, or the key won't be visible.

  5. Index into File Search

    Start narrow. Two Acts you can verify by hand is a better first test than 695 you can't.

    python ingest.py --acts 265,177

    Resumable via corpus/store.json; already-uploaded Acts are skipped, since indexing is billed per token once.

  6. Run it

    streamlit run app.py

    Opens at localhost:8501. The sidebar switches between Plain English and Legal detail, and can scope a question to one Act number.

  7. Verify before scaling

    Ask 10–15 questions you can check against the printed Act. What matters is not whether the prose reads well — it's whether the cited section number is the section that actually says it. Only then index the rest.

    python ingest.py

What went wrong

Every one of these was found by inspecting output, not by reading code. Each produced answers that looked fine.

The lettered-section bug is the instructive one. The first fix — allowing lowercase — recovered 299 sections and looked like success. The count only reached zero once the invisible EN SPACE was also handled. A partial fix that improves a metric is the easiest kind of bug to declare solved, and it happened three times here before the pattern registered.

Measuring it

Every fix above looked correct when it was made. Several weren't. That is what the eval is for.

eval.py runs 22 questions whose answers are known in advance and scores Act number, section number and key figures separately, so a failure says which part broke. It exits non-zero, so it can gate a rebuild.

The first baseline run scored 18/21 — and triage found the eval was wrong more often than the system was. Of six failures across two runs, one was a real defect. Two other cases were passing for the wrong reason: they scored green for refusing questions about the EPF Act and SOCSO, but both Acts had since been indexed. The eval was rewarding false refusals — the exact failure it exists to catch. Those cases were written when two Acts were indexed; scaling to 709 silently invalidated them.

After the corpus rebuild the same suite runs 22/22, with two cases confirmed fixed and no regressions. The value is not the score. It is the diff.

What it can't do

Stated plainly, because a legal tool that hides its gaps is dangerous.

  • No case law. Malaysian judgments are paywalled behind CLJ and LexisNexis. The assistant refuses these questions rather than guessing — verified working.
  • No subsidiary legislation, state enactments, or Syariah law. Federal principal Acts only.
  • No Federal Constitution. Excluded until its annotation apparatus can be parsed properly.
  • No Contracts Act 1950. AGC publishes it only as a scan with no text layer at all. Recovering it needs OCR, not better parsing.
  • Acts needing OCR are silently absent — check skipped.csv before assuming coverage of any particular statute.
  • Consolidated snapshots, not live law. Amendments after each reprint date aren't reflected. Always verify at lom.agc.gov.my.
  • It is not a lawyer. The Legal Profession Act 1976 reserves the practice of law to admitted advocates & solicitors. This is positioned as legal information, and the prompt bans advice phrasing — but before letting anyone else use it, talk to a Malaysian lawyer.
