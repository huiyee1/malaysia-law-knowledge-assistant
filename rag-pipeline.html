How 6,532 government PDFs become a chatbot that cites the section it read — and declines when it hasn't read one.

Steps 1–4 run once, offline. Steps 5–10 run on every question. The numbers pulse in order.

Why embeddings, not keywords

The reason a vector database is here at all, measured on this corpus.

Someone asks “how much holiday do I get”. The statute says “paid annual leave”. Those phrases share no words, so keyword search returns nothing. An embedding model maps both into the same 3,072-dimensional space, where meaning becomes distance — and the right section is simply the nearest point.

Terms, and what they are here

The same vocabulary, bound to concrete values in this build.

RAG
Retrieval-augmented generation. The model is given source text at question time instead of recalling facts from training. Removes the hallucinated section numbers that make a general model useless for law. retrieve → augment prompt → generate
Corpus
The cleaned, structured body of source text. Built by extracting Malaysian federal Acts from AGC PDFs and splitting each into its individual sections. 976 Acts · 32,387 sections · sections.jsonl
Chunking
Cutting the corpus into retrievable units. Split on the Act's own section boundaries rather than a fixed window, so every chunk is a legally coherent unit that carries its own citation header. 1 section per chunk · ≤512 tokens
Embedding
A vector of numbers encoding a passage's meaning. Similar meaning produces nearby vectors, which is what lets "holiday" find "annual leave". gemini-embedding-2 · 3,072 dimensions
Vector database
Stores the embeddings and answers "which are nearest to this one?" quickly. Rented rather than built — that removed roughly 200 lines of database plumbing. Gemini File Search · 709 documents
Cosine similarity
The angle between two vectors, used as the nearness measure. 1.0 is identical, 0 unrelated. Retrieval returns the top-k highest scorers — always something, however poor the match. no minimum-score threshold exists in the API
Grounding
Requiring every claim to come from retrieved text, with the source named. Enforced by the system prompt, not by code — and therefore something to test, not to assume. 22/22 eval cases passing
Metadata filter
A hard constraint applied before the vector search, unlike similarity which is a soft preference. Scopes a question to a single Act. act_no="265" → Employment Act only

Where hallucination is actually stopped

Not by the vector database. It has no idea whether its results are any good.

Nearest-neighbour search always returns its top-k, at any score, and never signals "nothing here". Retrieval hands over its best guesses regardless of quality — a question about Singapore law will still pull Malaysian employment sections, because those are genuinely the closest points in the space.

The refusal happens at step 10, in generation. The system prompt instructs the model to answer only from the retrieved text and to decline otherwise, so it reads the chunks and judges whether they actually answer the question. That is a semantic judgment made by a language model, not a numeric filter, and nothing in the code enforces it.

Which is why it is measured rather than trusted: 6 of the 22 eval cases ask questions whose answers are outside the corpus — foreign law, case law, state enactments, a fabricated 2027 amendment — and check that it declines instead of confabulating from a plausible neighbour.

Pipeline built on Gemini File Search and gemini-3.7-flash. Source documents from the Attorney General's Chambers of Malaysia. Similarity figures measured on the live store.
